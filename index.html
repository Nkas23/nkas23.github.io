Data Model

Schema Design

Eight tables designed for a real mobile app, built the way a company database would be structured, with proper relationships, indexes, and security from day one.

// database/schema.sql 8 tables · 11 relationships · 10 indexes
UUID over Integer IDs
Globally unique, non-guessable, and safe to use across Supabase and Snowflake without ID conflicts. Integers are sequential and predictable, a security risk in any public API.
Computed duration_minutes
PostgreSQL calculates it automatically from ended_at minus started_at. This removes business logic from the app layer and guarantees the value is always mathematically consistent.
user_id Denormalized into GPS and Catches
At scale, GPS events grow into millions of rows. Adding user_id directly removes a join and makes regional queries significantly faster. A deliberate performance trade-off.
Row Level Security on Supabase
Without RLS, any authenticated user could query all catches from all users. With RLS enabled, the database enforces privacy at the row level regardless of what query is run.
10 Strategic Indexes
Indexes on user_id, session_id, species_id, tier, county, and started_at eliminate full table scans. At millions of GPS rows the difference between indexed and non-indexed queries is seconds vs milliseconds.
GPS Partition Strategy at Scale
GPS events are the highest volume table, continuous pings throughout every session. At scale, partition by month on recorded_at in PostgreSQL and use clustering keys in Snowflake. Data older than 12 months moves to cold storage.

Build Log

Project Phases

Building a real app means building real infrastructure. Here's how the data architecture behind Reel came together, from schema design to a live analytics layer.

Phase 01

Foundation, Schema & ERD

Designed 8-table PostgreSQL schema (users, subscriptions, species, regulations, fishing_sessions, gps_events, catches, social_posts), deployed to Supabase East US, built ERD and data dictionary.

✓ Complete
Phase 02

Synthetic Data Generation

Built deterministic Python seed script using Faker with random.seed(42), generating 2,720 records across all 8 tables. Data loaded to Supabase successfully.

✓ Complete
Phase 03

Snowflake + dbt Pipeline

Provisioned REEL_WH warehouse with Bronze/Silver/Gold schemas. Wrote Python Bronze ingestion script and 12 dbt models (7 Silver views + 5 Gold tables). All models passing in dbt Cloud.

✓ Complete
Phase 04

Power BI Dashboard

Connected Power BI Desktop to Snowflake Gold layer via Import mode. Built 6 KPI visuals covering MRR, conversion rate, revenue by tier, species leaderboard, and regional activity, with a dark professional theme.

✓ Complete
